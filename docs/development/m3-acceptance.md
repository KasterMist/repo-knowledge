## Windows generation network differential (2026-10-27)

The maintainer reported TURN_FAILED/generation-turn/network with no HTTP status from the actual isolated Windows generation command, while ordinary official Codex conversations still worked. Independent inspection found no creation candidate and canonical SHA-256 still equal to the initial demo. This actual UI attempt failed; do not count it as generation acceptance or as an authentication failure.

The development-tool environment supplied unreachable loopback proxy variables, and the disposable editor launcher inherited its environment. However, a controlled ordinary-host retry with those variables absent also returned the same error; inherited test proxies alone do not explain every failure. Ordinary-host unauthenticated HTTPS probes to official ChatGPT/OpenAI origins timed out before an HTTP response. Windows had an existing system proxy but no persistent HTTP/HTTPS/ALL_PROXY variables. An explicit request through that existing system proxy obtained an HTTP response from the ChatGPT origin. These origin probes are transport evidence, not authenticated model access or an upstream-availability guarantee.

Changing only the test-process proxy routing to that existing system proxy made the same production adapter save a valid one-page creation candidate from the self-authored two-file scope: submittedTurns=1, observedTokens=6249, published=false, canonical bytes unchanged. The two-page selection is a maximum, not a required count. Current-source/output validation passed before saving. No target source execution, persistent proxy/login/model/provider changes or automatic retry occurred. The sample is a successful Windows core-generation result; actual corrected-environment editor confirmation, Remote SSH generation and human review/publication remain unaccepted. The SSH failure has not been attributed to the Windows cause.

The disposable Windows UI must use a fresh editor process with the intended network environment; reloading an existing window need not replace the parent process environment. Private launch helpers/paths/proxy endpoints stay outside public source. The plugin currently inherits the extension-host process environment and does not bridge Windows system/editor proxy settings into Codex automatically. Preserve that limitation in support guidance; do not silently delete or replace a user's proxy variables in product code. Continue from corrected-host UI acceptance, then T16 checkpoints/result adoption/idempotent explicit retry.
