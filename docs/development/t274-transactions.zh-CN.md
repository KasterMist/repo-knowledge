# T27.4b：共同事务与迁移恢复

更新：2026-11-15。跟踪 [Issue #58](https://github.com/KasterMist/repo-knowledge/issues/58)。这是显式 core 模式的事务实现，默认编辑器/随包 MCP 仍为 v1；没有新的用户命令、设置或自动迁移。整体 T27.4 未完成。

## 已实现的核心操作

| 操作                                      | 审阅与提交边界                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| previewWikiMigration / migrateWiki        | v1→空文章 v2 的独立审阅；原始字节备份；保留旧候选清单，不自动采用                |
| previewWikiCreation / publishWikiCreation | 文章与关联卡片一次目标、同锁一次原子提交；已有人工文章不变，新根文章顺序明确追加 |
| previewWikiRollback / rollbackWiki        | 创建头整批移除，文章导出留在历史；仅未发生后续提交的迁移可原字节恢复             |
| recover                                   | prepared v3 按实际两侧标记 committed/aborted；分歧拒绝，不覆盖当前知识           |

共同使用既有 `.publication.lock` 和 history 原子替换机制。新 journal 3 增加操作类型、文章/卡片 ID、原始两侧 SHA-256、此前 committed 事务 ID；知识 schema 仍独立为 v1/v2。全文快照差异和 retainedMetadata 清单/历史版本共同进入审阅 token，确认时、替换前重新校验，防止源码、Git、正文或清单变化后继续提交。

候选在迁移前生成时，只能在当前基础恰好等于已提交空文章迁移目标的条件下显式重新核验。完整源码包依照旧基础核对后，按当前源码重新校验输出；审阅明确显示 adaptedFromMigration，旧候选字节及其基础记录不改写。其他基础变化直接拒绝。这样已有 T27.3 候选不会被悄悄重新标版本。

旧元数据留在原位，清单最多 128 个常规 JSON/4 MiB，另受每文件 1 MiB 和目录数量限制；活跃 lease、临时文件、越界/符号链接和 prepared 历史先拒绝。已绑定 Git 工作树切换分支或 HEAD/index 变化会阻止旧确认；首次绑定也把 wiki-candidates 纳入旧数据拒绝清单。

迁移恢复要求原字节和事务链都匹配。创建再移除导致内容相同也不能回退更早迁移；相反，合法恢复后重新审阅的新迁移仍可回退。文章/卡片移除后 ID 永久保留；生成请求只增加既有/退休文章 ID 清单，不发送旧文章正文或人工理由。普通单卡发布在 v3 历史后继续保留文章，只把旧引用标为需复核。
