# Wiki 阅读体验交付

续接：PR #77 五项 CI 已通过并合并。正式文章以仓库/存储/工作区 URI 为键复用阅读标签，侧栏点击切换同一阅读器；候选预览保持独立。消息串行处理，避免快速点击丢失或旧正文覆盖新选择；配置/工作区变化关闭旧阅读器并清除复用记录。空库新增“选择范围并生成 Wiki”按钮，仅打开当前仓库生成表单，仍需要范围和发送确认，未发布候选有明确提示。

本轮验证：完整检查 156 单测、7 集成和 VSIX 打包通过；Windows VS Code 1.117.0 真实隔离安装宿主通过新增断言（侧栏文章返回同一 panel、并发导航按顺序返回两个指定文章）和原有正式正文刷新/源码跳转、候选隔离、配置失效与独立 MCP 检查。未测试官方 Codex 对话，未做本轮真实 Remote SSH 或屏幕视觉验收，不以宿主测试冒充截图效果确认。

用户目标：生成后能直接通过文章目录阅读 Wiki；管理流程不能挤占主要阅读空间。参考用户提供的 Qoder 截图，不访问业务源码、不触发外部生成。

本次实现：阅读器内的 Repo Wiki 目录搜索、文章数、当前文章高亮、父子目录上下文；中部正文以章节排版，右侧本页目录跳转；卡片内部标识与源码证据收进可展开详情，过期警告仍可见。宽屏三列，窄屏折叠成上下布局。搜索仅过滤文章标题，不是全文搜索；不发起模型请求。侧栏 Cards/Drafts/Proposals/New Cards/History 首次默认折叠，已有用户布局不会强行覆盖。

已发布文章仍由 Open Published Wiki 或侧栏文章点击打开；生成候选仍需审阅发布后进入正式目录。本次不自动生成、不导入 Qoder 私有格式、不取消发布确认、不将卡片存储冒充完整文章。

安装开发 VSIX 才能检查此效果；公开 M1 alpha 不包含当前文章阅读器。实际安装、窗口观察和 Remote SSH 验收结果须分别记录，单元测试不等同于视觉验收。接下来继续整合侧栏阅读入口、复用文章标签，以及空库/候选引导和实际窗口验收。
