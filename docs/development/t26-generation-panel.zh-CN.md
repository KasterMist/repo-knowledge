# T26：统一生成面板

日期：2026-11-14。跟踪 [Issue #56](https://github.com/KasterMist/repo-knowledge/issues/56)，产品总门禁 [Issue #54](https://github.com/KasterMist/repo-knowledge/issues/54)。

## 用户流程

1. 打开主页，点击“打开生成面板”，或执行 Open Generation Panel。多根工作区先选择仓库；选定后固定该 folder，页面显示真实执行宿主。
2. 在同一表单填写 include/exclude 相对 glob、语言、文件数、总 KiB 和最多候选卡片数。每文件固定上限 64 KiB；单次 2/4/8 张卡片；模型总时限 60 秒、输出 64 KiB，并非精确费用上限。
3. 点击“预览源码范围”，仅静态扫描，在页内查看完整文件清单、字节数、覆盖和跳过统计。空范围或覆盖不完整不能生成。修改任意字段需重新预览。
4. 点击“确认并生成候选”，保留原生模态源码发送确认；只有再次明确确认才启动受限生成。页内显示确认/运行阶段；既可用页面按钮，也可用编辑器通知取消。生成结果仍为待审阅候选，不自动发布。
5. 失败后页面显示固定分类或校验错误；用“找回结果 / 明确重试”选择已有任务。仍保留原生任务选择器：有结果只找回；无结果的重新尝试必须再次确认源码发送，绝不自动重试。页面显示结果数量、状态及模型是否启动等元数据。
6. “查看新增待审阅”打开现有侧栏，后续审阅和确认发布仍沿用既有流程。独立文章及图形正文审阅分别属于 T27/T28。

关闭生成页面、改变插件配置或工作区文件夹会取消该页面拥有的活动操作；已保存候选不删除。晚到的取消不把成功保存的结果伪报为未保存。配置/工作区变化会关闭旧面板，重新打开后重新预览。

## 实现边界

`generation-view.ts` 是带 nonce/CSP 的 Webview 表单及浏览器事件循环，所有路径、错误和文件名使用 HTML 转义或 DOM textContent。页面不加载外部脚本/资源；不允许 command URI、本地资源或消息指定的路径/命令。

`generation-session.ts` 校验严格消息形状、表单长度/整数/相对 glob，并串行执行该页面拥有的操作。生成请求必须同时匹配缓存的完整表单和规划 ID；编辑、错误及完成后不保留可误用的旧预览。此内存状态不是新的持久知识格式。

`generation-panel.ts` 将会话固定到工作区 folder，复用 `ScanWorkbench` 的静态扫描及 `GenerationWorkbench` 的已有任务、源码确认、预算、锁和结果恢复。后者生成前再次比对规划 ID；另一页面/命令替换规划后拒绝使用。关闭页面的 AbortSignal 与已有通知、宿主生命周期、配置变化、任务期限合并。

旧 Plan Knowledge Generation / Generate Knowledge Candidate 等命令继续兼容；主页改为统一面板入口。内核/MCP 协议、知识持久格式、登录、provider 和代理设置均未改变。

## 验证与局限

离线自动化覆盖表单边界/未知消息/路径注入、真实自编 Unicode 夹具扫描、旧表单和覆盖不完整拒绝、并发拒绝、取消/关闭、通知取消分类、晚取消与已保存结果、模拟结果找回，以及实际随包浏览器脚本的无启动工作/表单绑定/编辑失效/文本节点/按钮状态。模拟生成/恢复不代表真实模型访问。

Windows VS Code 1.117.0 实际 VSIX 隔离宿主已验证：打开面板、两文件页内预览、表单变化拒绝、另一预览替换后的规划 ID 拒绝，均在 backend/model 访问前；正式知识字节不变。双根目录宿主检查增加固定第二仓库预览。Node 24.19.0 完整检查通过：104 单测、5 集成及实际 VSIX 打包。精确 head 的 Windows/Linux 五项 CI 与合并记录见 Issue #56。

本轮不做新的模型推理，也不冒充新的官方 Codex 对话、Remote SSH 人工点击或完整浏览器视觉验收。已有 M3/T20 真实生成证据保持有效；新前端的确定性测试与它们分开记录。尚未生成独立 Wiki 文章、全库多阶段编排，也没有发布新版本。
