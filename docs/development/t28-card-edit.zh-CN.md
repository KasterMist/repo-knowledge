# T28：图形卡片编辑、草稿恢复与冲突处理

更新：2026-11-18。功能优先，视觉美化和管理区整合暂缓。整体 T28 仍未完成。

## 已实现

2026-11-26：PR #73 五项 CI 通过并合并；文章说明开始实现纯编辑内核，范围及剩余持久化/发布门禁见 [说明编辑续接](t28-article-notes.zh-CN.md)。尚无用户可操作的文章说明编辑入口。

2026-11-24：Review Knowledge Changes 保留原 JSON 报告并打开“知识变化与维护”面板，列出报告卡片及状态。按钮可打开固定卡片的正文表单，或进入固定卡片的单卡更新；后者仍必须有当前完整范围规划并经过既有源码发送确认。消息仅接受报告内下标和固定动作，不接受路径/命令；宿主确认工作区、信任和正式快照，配置/工作区改变关闭面板。生成结果仍通过原有候选差异/确认发布流程处理；没有自动重新绑定文章、批量更新或模型后台工作。最终真实 GUI/Remote SSH 验收保留。

2026-11-23：卡片正文表单新增显式 Markdown 预览，沿用 Wiki 的受限 token 渲染器；原始 HTML 转义、链接不可执行、图片不加载。预览允许尚未填写修改理由，但仍限制正文长度和消息字段；不读取源码、不调用模型、不写草稿/候选/正式知识。修改输入后清除旧预览，避免把旧内容当作最新。此为编辑便利功能，不代表源码证据已验证或整个 T28 完成。

卡片右键或 Edit Card Body 打开正文/修改理由表单，宿主固定所选仓库、原卡片和快照。客户端不能指定 ID、修订、路径或证据。Save Draft 显式保存现有 format 2 草稿，不提交候选、不覆盖正式知识；同一页面重复保存相同输入复用同一份，修改后再保存创建新副本，保留旧版本。Resume Card Body Draft 可从草稿列表右键或命令恢复正文与理由；非正文元数据变更、旧无基线或合并草稿须走原有流程，避免悄悄丢字段。未保存输入关闭后仍会丢失。

恢复保留原始基线；正式知识已变化时提交/新保存拒绝，不将旧正文冒充最新基线。保存候选继续使用 propose 的证据/修订/快照校验，成功后禁止重复提交。工作区和配置变化关闭旧表单，并拒绝异步打开旧上下文。

Resolve Card Conflict 显示 base/current/proposed 和每个冲突字段。每项须明确选择保留当前或采用建议；正文另可手工整合。未处理或伪造字段拒绝，非冲突字段采用既有安全合并结果。宿主固定原候选、token 和字段来源，核心重新核对当前三方报告，只保存已处理的现有 format 2 合并草稿及 receipt。新入口不要求手改 merge.resolvedFields，不直接提交/发布。通过 Drafts 的 Submit Draft for Review，再 Review Proposal Diff / Publish Reviewed Proposal 单独确认。

没有新持久格式；复用 ADR 0006/0012 的 draft/proposal/receipt 和迁移回退规则。旧 JSON 编辑入口保持可用。所有正文与理由有界、HTML 转义，nonce CSP、禁用资源/command URI；不调用模型。实际文件未保存拒绝写入，只读虚拟知识文档不误拦截。
