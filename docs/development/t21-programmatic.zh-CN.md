## 程序化协议

使用官方 [app-server 协议](https://learn.chatgpt.com/docs/app-server)创建独立 ephemeral
线程，捕获 completed MCP 调用的真实参数/结果和最终答复，不操作用户聊天窗口。
每个进程沿用既有登录/provider，只在进程参数指定实验模型 `gpt-6.1-sol`、effort `low`，
不改用户默认配置；不推定 `low` 与人工 UI 的 `light` 标签完全等价。

每次创建新的自编源码/外部存储，源码与卡片和原案例同指纹。不同于原 IDE 任务：
本轮把同一份源码文本直接附在问题后面，关闭 shell、文件浏览、web、apps/plugins、
辅助 Agent、hooks/memories 等执行入口，只配置本例 status/search/read 三项 MCP。
新协议和原人工协议不能直接拼接成因果对照。

纯文本生成器禁用的 Code Mode/host 会妨碍本例模型访问工具，因此知识实验单独启用
这两项工具编排基础设施，仍检查其他执行功能关闭、只读 sandbox、无外部指导文件，
并核对 MCP 目录只有指定的三项。生产生成器的禁用策略与版本 allowlist **没有放宽**。
模型侧工具调用事件比“目录里列有工具”更强；事件的反应式检查本身不是安全沙箱。

Windows 使用现有 CLI 0.164.0-alpha.11.1；远端已更新至 0.167.0-alpha.4.1，后者只通过
实验器的单独协议/配置预检，不因此宣称生产生成器支持该版本。网络仅在自有子进程
内沿用既有 Windows 系统代理/远端 VS Code extension-host 代理环境；不复制 token，
不修改持久代理、登录、provider、信任策略或用户级 Codex 配置。

用户配置、凭据、主机地址或绝对私有路径。原始文件留在私有实验目录。

| 宿主             | turn/start 提交 | 实际完成的 MCP               | 总耗时（含启动/配置） | 观察 token |
| ---------------- | --------------- | ---------------------------- | --------------------- | ---------- |
| Windows 原生进程 | 1               | status、搜索“预留”、读取两卡 | 36,135 ms             | 25,201     |
| SSH Linux 进程   | 1               | status、搜索“预留”、读取两卡 | 43,907 ms             | 26,567     |

每次模型回合上限 60 秒，观察 token 阈值 40,000，客户端无自动重试。阈值是反应式
停止条件，不是硬计费上限；turn/start 数不等于 provider 推理请求/费用数量。

两份最终答复均正确说明重复 token 返回 quantity=3 的同一收据、库存仍为7；均引用
理由卡解释作者提供的终端重放背景，并指出 current 源码不能证明历史动机。真实
status/read 返回同一预期快照、两卡 r1/stale=false/current；源码/规范知识逐字节未变，
没有创建候选或发布。捕获事件类型为 userMessage、agentMessage、mcpToolCall，以及
Windows 的 reasoning 类型（仅类型记录，不保留内容）。这证明两个程序化进程完成
一次明确要求下的知识使用，不证明稳定主动检索、全库质量或官方 IDE 的对应交互。

## 失败与调用账本

原始失败不删除、不把后续修订覆盖成首次成功：

1. Windows v2 四个独立回合完成文本答复，但评估器误用了纯文本生成的工具禁用
   配置。目录存在三工具并不能证明模型可调用；显式组报告 host disabled，四回合
   未捕获 MCP。它们不计作有效知识组或自然不调用证据。
2. SSH v2 第一次回合 60 秒期限结束，后续组跳过；未把未知 token 当零。此后仅在
   自有子进程沿用已存在、无 URL 凭据且多宿主一致的 VS Code 代理环境。
3. Windows v3 的一次定点验证由断言终止，未留完整细节，原因保留未知。
4. SSH v3 已完成 status/search/read/read，但观察 token 18,855 超过初设 16,000，
   接收器断言停止，未收最终答案。初步怀疑协议事件只是调查方向；已留的部分事件
   证明实际触发的是预算阈值，不能归为插件或协议错误。
5. 明确声明新阈值后，两端各另开一次 v4 定点验证，得到上节完整结果。本轮停止
   模型调用，不为了凑满结果继续反复生成。

全部真实 turn/start 提交为 Windows 6 次、SSH 3 次，共9次；预检与无认证 loopback
mock 不计真实推理。已记录 token 项之和为98,994，另有未知项，不代表总用量或费用。
没有客户端自动重试；后端内部重试情况未完整枚举。各轮属于不同实验修订，不能用
最终成功替换早期失败，也不能计算“9次中成功率”来表达知识效果。
