# T20 单卡增量维护 beta 进度

更新：2026-11-11。跟踪 [Issue #47](https://github.com/KasterMist/repo-knowledge/issues/47)。

T17–T19 已完成本次范围验收；T20 正在将其串成显式增量闭环。此前模型命令只新增
卡片，因此本次增加 Generate Card Update：用户确认源码范围与一张现有卡片，
受限后端提交一次生成任务，校验同 ID 的当前源码证据，只保存普通更新候选。
Recover Incremental Result 读取尝试/候选/历史，不调用模型或自动重试。

已实现单卡输出边界、共享受限 turn、稳定候选 ID、取消清理、耗时/请求尝试/
可用 token 统计、失败分类脱敏，以及现有快照/证据/工作树/人工修订保护。
协议请求尝试数不是账单调用数；无用量通知时 token 为 null。格式与降级见
[ADR 0013](../architecture/adr/0013-incremental-attempts.md)，操作见
[增量手册](../user/incremental.zh-CN.md)。

自动化：确定性回复的自编夹具跑通影响报告→候选→重复找回→审阅发布→回退，
并验证其他卡片不变、失败/取消不留候选、旧规划和错误 ID/引用拒绝。协议 peer
另测实际 turn/start 尝试计数和本地预算拒绝计数为零。模拟回复不计真实模型验收。
回退前必须恢复与旧证据相符的自编源码；旧哈希不匹配时回退应拒绝。

锁定完整检查已通过 93 单测/5 集成；最终打包宿主与精确 head CI 将另记结果。
