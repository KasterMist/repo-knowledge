## 评估的问题与控制条件

四工具可用、Agent 自主检索、答案质量和独立对话复用分开记录。新案例改用库存预留，
不沿用之前反复验收的空字符串问题。每端固定以下四个全新、互不复制历史的对话：

| 组别     | 工作区             | 知识可见性                         | 提问                                 |
| -------- | ------------------ | ---------------------------------- | ------------------------------------ |
| baseline | baseline/workspace | 不暴露知识 MCP，也不读外部知识     | 普通任务                             |
| natural  | natural/workspace  | 只暴露本例对应的知识 MCP           | 与 baseline 完全同文                 |
| explicit | explicit/workspace | 对应独立、同内容的知识 MCP         | 明确要求实际调用三工具，再做同一任务 |
| reuse    | natural/workspace  | 复用同一持久知识库，但新建独立对话 | 新问题，不给卡片答案                 |

两端共八次对话，每次只发送一次指定问题；错误和未调用如实保留，不追问到满意为止。
固定同端模型、推理设置、Codex/VS Code/插件版本与网络环境；记录不可固定的差异。
两端结果分别评估，不把不同模型/宿主的耗时混成性能排名。顺序固定 baseline → natural →
explicit → reuse，避免先显示答案影响基线；固定顺序仍有顺序偏差，不能作因果证明。

natural 不在用户提问或额外 AGENTS.md 中要求调用工具；但 MCP 自身包含工具描述及
“检索后核对证据”的 server instructions，这属于处理条件，不能声称完全没有提示。
baseline 不允许其他已配置知识库、既有卡片、评分文档或旧聊天参与。新对话并不自动
消除其他系统记忆/工具影响；无法核对的标记 accessVerified=null，不能列为合格基线。
目录隔离不是权限沙箱，不能把有文件访问能力等同于保证没有串读。

## 准备（不调用模型）

使用仓库锁定 Node 执行：

```text
node scripts/evaluate.mjs prepare
```

每次创建新的系统临时目录，输出具体路径和源码/知识指纹，不覆盖已有记录。
三份工作区只包含完全相同的 `src/reservations.ts`；不含答案、卡片、AGENTS 或评估说明。
natural/explicit 各有工作区之外的独立 store；reuse 使用 natural 的同一工作区/store。
`reviewer/observations.json` 是全未知的记录模板，留在评审端，不在受试编辑器打开。
不要用工程仓库或旧演示代替此路径，避免继承工程指导或混用 MCP 存储。

在各宿主打开相应工作区，使用现有明确配置预览把 MCP 指向该 workspace/store，
核对服务与源码/快照指纹；不要修改模型、登录或代理。工具名称相同不证明连接正确。
基线必须确认知识工具未暴露，后续组必须确认只暴露正确服务；不能仅靠对话中
“不要使用”来代替隔离。若现有全局配置不能隔离，先停止并记录，准备可审阅的
临时配置差异后再按授权操作；脚本不会替用户改配置。不要把用户配置或凭据提交到 GitHub。

## 固定提问

baseline 和 natural **逐字使用同一段**：

```text
请静态审阅 src/reservations.ts：初始库存 10，同一 token 先 reserve(token, 3) 再 reserve(token, 7)，第二次返回什么、剩余库存多少？为什么允许相同 token 携带不同数量？请区分源码事实、已记录的设计理由和无法确认的推测，注明依据。不要运行源码、测试或构建，不修改任何文件。
```

explicit 在上段之前加以下一行（完整准确文本由 scripts/evaluation.mjs 的 prompts 导出）：

```text
请实际调用 Repo Knowledge 的 get_knowledge_status、search_knowledge（搜索“预留”）和 read_knowledge，再完成下面任务；若工具没有直接暴露，请如实报告，不用脚本模拟。
```

reuse 必须新建独立对话，不复制旧答复，只发送：

```text
请静态判断这个项目中，同一个 token 已成功预留 3 后，再携带数量 0 请求，会抛 quantity 错误还是返回原收据？说明依据，并区分源码事实和设计理由。不要运行源码、测试或构建，不修改任何文件。
```

## 评审端评分（不要放进受试上下文）

| 字段           | pass 的可核对条件                                                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| sourceFacts    | 前三组：返回第一次 quantity=3 的同一收据，剩余库存 7，第二次不再扣减；reuse：返回旧收据，不触发 quantity 验证，说明查重在验证之前 |
| humanRationale | 明确恢复卡片作者提供的“旧版终端离线重放可能重算数量、以首次交易 token 收据为准”理由，并承认它是记录的人工理由                     |
| attribution    | 源码事实有实际文件/行或 current 证据；人工理由与源码推断分开；无记录时明确不能确定，不能编造终端历史                              |
| noExecution    | 可见工具记录没有执行源码/测试/构建，也没有修改文件；仅回答声称没运行而无观察，记 unknown                                          |

每项 pass/fail/unknown，独立判断，禁止把回答中出现关键词自动算正确。
baseline 不知道人工理由是合理限制：humanRationale=fail（未恢复），但诚实说明未知
可以 attribution=pass，不处罚诚实拒绝编造。知识组得到额外人工理由，属于信息条件
不同；只能解释为该记录的可获得性，不能说是同等信息条件下推理能力提升。

每次保存脱敏的完整问答及可见工具调用/返回到 reviewer 下的简短英文文件名 `.txt`，
包括错误、不调用、拒绝和越界。记录文件 SHA-256、准确模型和版本、UTC 时间、独立
会话标签及实际观察的工具列表；空数组代表观察到没有调用，null 代表未知。
toolObservation=visible-calls 需评审者看到调用轨迹；只有回复自称调用填 user-report。
elapsedMs 和 observedTokens 无可靠来源就保留 null，不能当零；两者不是计费数据。
environment.reasoningEffort 记录实际推理级别，未知填 null；旧记录没有此项仍可读取，
但缺失或不同的推理级别不能认定为相同实验环境。
这些实验文件默认留在临时目录，不自动上传；公开前逐项去除用户名、路径和账户信息。

```text
node scripts/evaluate.mjs report <临时目录>/reviewer/observations.json
```

报告校验格式、任务/快照指纹和逐份正文校验和；缺项保持 missing/not-run，不能通过
复制同一会话、用模拟回复或给未执行项目打分补齐。accessVerified=false、非独立会话、
工具观察不足及使用了知识的基线会保留但 ineligible。检查器不证明人工记录真实，
coverageComplete 只表示记录/隔离条件齐备，不表示所有评分通过或效果显著。
