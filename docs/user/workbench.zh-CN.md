# M2 知识工作台（开发候选）

当前公开的 v0.1.0-alpha.1 是 M1，不包含本页的新工作台。M2 从开发源码构建并验证；正式发布时另设版本，不替换旧资产。工作台不调用模型、不生成 Wiki。首次生成入口属于 M3，由用户明确发起。

## 浏览同一份知识

运行 **Repo Knowledge: Open Knowledge Workbench**，或点击活动栏书本图标。

- **Repo Wiki**：按卡片第一个源码 scope 路径组织，再显示卡片；当前不是独立编写的文章目录。
- **Cards**：按标题浏览所有卡片。点击查看只读正文和证据，展开卡片后点击证据跳到源码。
- **Drafts / Proposals / History**：人工草稿、待审阅候选和发布历史。

每个工作区文件夹独立绑定知识目录。命令面板需要选择条目时，先选择对应仓库。缺失、越界或失效的来源会报错或显示状态。**Refresh Knowledge** 重新读取知识；不会触发生成。只读卡片视图是打开时的快照，发布后重新打开；MCP 每次请求重新读正式快照。

## 人工编辑与发布

1. 在 Cards 中右键卡片，选择 **Edit Card Draft**。扩展在外部知识目录创建草稿 JSON，原知识快照保持不变。
2. 编辑 `proposedCard.body`、标题等内容，以及 `reason`。原文会完整复制，人工设计理由不会被表单自动裁掉。保留 ID、基础快照和基础修订号，`proposedCard.revision` 已设置为原修订加一。保存文件。
3. 在 Drafts 中右键对应草稿，选择 **Submit Draft for Review**。未保存的知识编辑器会阻止提交。校验成功后保存独立候选，草稿保留；这一步不发布。重复提交会另存候选，建议每次修改后只提交一次。
4. 点击 Proposals 中的候选，或运行 **Review Proposal Diff**。左右两侧为只读的旧卡片与候选。核对正文、理由、引用、范围和修订号；源码 hash 有效只说明引用版本匹配，不证明所有文字结论正确。
5. 在同一候选上选择 **Publish Reviewed Proposal**，检查弹窗后点击 **发布 / Publish**。若尚未审阅，第一次只打开差异，检查后再运行发布。取消不改原快照。发布前会重新检查保存状态、候选、基础修订、快照和源码证据；变化时拒绝，请重新读取并审阅。
6. 发布成功后重新打开卡片，或让 Codex 调用 MCP read/status。二者读取同一 knowledge.json；无需重启 MCP。

当前仅编辑已有卡片，不通过手改 JSON 绕过校验创建新卡片。旧候选不会自动合并到新快照；需要基于最新卡片重新编辑。模型三方合并与分支隔离属于 M4。

## 回退与中断恢复

点击 History 查看该次快照前后差异。只允许回退当前正式快照对应的最新已提交事务：右键 **Roll Back Knowledge**，先检查将恢复的卡片差异，再运行一次并确认。历史内容会保存为更高修订号，例如 r2 回退为 r3；源码不回退。旧内容的证据已失效时拒绝回退，不能把旧结论伪装成有效知识。

发布采用独占锁、前后快照备份、文件同步和同目录原子替换。Windows 短暂文件占用只重试原子替换，最多五次，每次重检修订和证据；持续失败保留原文件并报错。不能保证所有存储设备的突然断电行为。

若提示 **STORE_LOCKED**，先停止其他发布并等待正常写入结束。若进程已经异常退出：备份整个知识目录，检查 `.publication.lock` 记录的进程确实已停止，再由维护者手动移除旧锁。不要在活跃写入期间删锁。扩展不会猜测锁已过期并自动接管。

若 History 出现 **prepared** 或提示 **RECOVERY_REQUIRED**，保留目录并选择该记录的 **Recover Publication Marker**。确认后仅在当前快照精确匹配前或后版本时补写 aborted/committed 标记，不覆盖知识。两侧均不匹配、日志损坏或缺失时停止并从完整备份人工处理。不要直接删除历史来消除报错。

每个元数据文件上限 1 MiB，草稿、候选或历史目录列表上限 200 项；达到上限前停止写入，备份并归档。保留当前历史头，归档后不能在界面回退被移走的记录。

## Windows 与 Remote SSH 验收

只使用自编三卡片演示，不在真实目标仓库改源码：

1. 在各窗口打开工作台，展开 Wiki、Cards，查看“读取”卡片并跳到中文源码路径。
2. 给该卡片创建草稿，仅在正文追加“人工说明：缓存中的空字符串会原样返回”。未保存时提交应拒绝；保存后提交，原卡片仍 r1。
3. 审阅差异；发布弹窗先取消一次，确认原卡片仍 r1。重新发布并确认，应变为 r2。让 MCP read/status 读取同一版本。
4. 打开该发布历史，按上述两步回退并确认，应恢复原正文且修订为 r3。再次读取 MCP，应同样看到 r3。
5. Remote SSH 全程保持同一远端连接，草稿、历史与源码文件都在远端，不能打开成本地 Windows 路径。

自动化工程检查、真实编辑器宿主、维护者手动点击和官方 Codex 对话属于不同证据，记录时分别说明。M1 已通过的官方 Codex 场景无需全部重做；本次只补 M2 新界面和发布后的读取。
