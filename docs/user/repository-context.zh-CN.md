# Git 工作树和分支隔离（T18 开发版）

此功能尚未发布。它不会切换分支、自动生成或调用模型。

## 新项目

1. 在 Windows 原生或 Remote SSH 窗口打开 Git 工作树。
2. 在该工作区设置 `repoKnowledge.storeDirectory` 为本宿主上的新外部目录。
   每个分支、工作树分别使用一个目录；SSH 使用 Linux 路径。
3. 运行 **Initialize External Store**，再运行 **Bind Repository Context**。
   检查当前工作区和分支后确认绑定。未确认不会写绑定文件。
4. 按原流程规划、生成、审阅和确认发布。MCP 使用同一工作区/存储配对。

切换到其他分支后，原存储会报告 `REPOSITORY_CONTEXT_CHANGED`，应选择该
分支自己的存储。切回原工作树/分支可继续读取原存储，不要删除绑定文件。
同一分支新提交可继续使用存储，但旧生成规划需要重新扫描。

## 错误与旧数据

- `CONTEXT_BINDING_REQUIRED`：当前 Git 存储尚未显式绑定。
- `LEGACY_CONTEXT_UNVERIFIED`：有旧规划、草稿、候选、任务或历史，不能推测
  它们的分支。完整备份保留，改用新存储并重新规划；不要逐个删记录来绕过。
- `REPOSITORY_CONTEXT_CHANGED`：工作树/分支不匹配，或规划后的 HEAD/暂存区
  改变。核对存储；必要时重新规划和审阅。
- `PLAN_CHANGED`：所选范围内保存的源码或文件清单发生变化，重新规划。
- `REVIEW_CHANGED`：确认前上下文或候选变化，重新打开差异审阅。

已有正式快照而没有待处理元数据的存储可以显式绑定；这只是接受其存储归属，
不会认证旧正文是否正确。普通证据检查仍会显示过期内容。

未保存的编辑器内容应先保存；生成使用磁盘上的所选源码。该功能不为全部
未选择文件建立 dirty 清单，也不与外部 Git checkout 建立原子事务。Git 元数据
单文件超过 1 MiB、符号链接或不支持的格式会保守拒绝；不要因此修改 Git 元数据。

旧版插件不识别绑定保证。升级/回退前完整备份，旧版只操作独立备份，不能与
新版同时写同一存储。详见 [ADR 0011](../architecture/adr/0011-repository-context.md)。
