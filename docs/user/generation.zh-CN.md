# 用户发起的知识生成：M3 开发状态

本页描述开发源码中的 M3 工作。公开 v0.1.0-alpha.1 仍为 M1；M2 已完成本次验收但没有单独 Release。M3 当前先实现 T14 扫描规划，尚不能生成新 Wiki 或知识卡片。

## 扫描规划

在受信任的 Windows 或 Remote SSH 工作区运行 **Repo Knowledge: Plan Knowledge Generation**，或在知识工作台的仓库节点右键选择该命令。多目录工作区先选择要处理的仓库，命令只处理这一个根目录。

依次选择：

1. 包含路径，例如 `src/**` 或 `src/**/*.ts`。使用 `/`，多个 glob 用逗号分隔；支持 `*`、`**` 和 `?`，Windows 也区分大小写。当前输入框不支持文件名中的字面逗号或 glob 转义。
2. 排除路径，默认排除 `dist/**,build/**,vendor/**,coverage/**`。
3. 未来生成的语言：简体中文或 English。
4. 最大文件数，默认 50，上限 200。
5. 总读取量，默认 128 KiB，上限 2048 KiB。界面每文件另限 64 KiB。

命令仅做静态文件读取，不运行源码、构建或测试，不启动 Codex，不上传文件。进度通知可取消。取消不保存规划，不改知识快照。默认排除常见凭据、Git/Agent/编辑器配置、工具环境与知识目录，不跟随符号链接。过滤不能保证其他文本没有敏感内容；后续生成还须另行检查并确认发送范围。

只读 JSON 预览包含入选相对路径、文件指纹、大小和行数，以及跳过项统计。`summary.limited=true` 表示触及限额或有未覆盖的读取，不能当作完整覆盖。二进制、范围排除和受限内容分开计数；没有入选文件也不会凭空生成内容。硬性目录遍历上限为 10,000 项、深度 32。这里的字节限额是静态读取上限，不是模型 token 或费用预算。

## 保存和重新检查

检查预览后运行 **Repo Knowledge: Save Generation Plan**。它会重新扫描，拒绝已变化的文件、范围或覆盖信息，然后保存到外部知识目录的 `plans/<UUID>.json`。文件只有路径、指纹、统计和语言/限额，不包含源码正文。保存不等于授权调用模型或发布。

若知识目录在源码仓库内，保存会拒绝；请按现有接入指南使用外部存储。规划预览仍可用。更改配置或工作区后请重新规划。保存过的规划不原地覆盖；如提示数量达到 200，请备份后明确归档旧规划。运行取消后可重新发起扫描，不会自动续扫或生成。

## 后续增量

T15 开发代码已增加 **Diagnose Generation Backend**，操作与脱敏字段见[后端诊断指南](codex-backend.zh-CN.md)。它不调用模型。接下来接入 Codex 独立生成任务，T16 增加调用限额、取消、检查点和失败恢复。模型访问诊断、生成成功、候选有效和用户确认发布是不同状态。M3 还需支持新卡片的候选审阅与发布，不能绕过 M2 发布保护直接写 knowledge.json。界面中当前没有可执行的“生成”按钮，避免把扫描成功误认为已生成知识。
