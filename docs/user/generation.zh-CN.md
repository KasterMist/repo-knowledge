# 用户发起的知识生成：M3 开发状态

本页描述开发源码中的 M3 工作。公开 v0.1.0-alpha.1 仍为 M1；本页命令需要新开发候选包。M3 已接入显式生成到候选的流程，Windows 与 Remote SSH 自编演示均已真实保存候选；结果找回、明确重试、确认框/进度取消与新批次发布/移除也已通过本次两端自编演示验收。M3 本次范围已完成，尚未发布；不代表任意大型仓库、全部模型或 Linux 桌面 Codex 均已验证。

## 扫描规划

在受信任的 Windows 或 Remote SSH 工作区运行 **Repo Knowledge: Plan Knowledge Generation**，或在知识工作台的仓库节点右键选择该命令。多目录工作区先选择要处理的仓库，命令只处理这一个根目录。

依次选择：

1. 包含路径，例如 `src/**` 或 `src/**/*.ts`。使用 `/`，多个 glob 用逗号分隔；支持 `*`、`**` 和 `?`，Windows 也区分大小写。当前输入框不支持文件名中的字面逗号或 glob 转义。
2. 排除路径，默认排除 `dist/**,build/**,vendor/**,coverage/**`。
3. 输出语言：简体中文或 English。
4. 最大文件数，默认 50，上限 200。
5. 总读取量，默认 128 KiB，上限 2048 KiB。界面每文件另限 64 KiB。

命令仅做静态文件读取，不运行源码、构建或测试，不启动 Codex，不上传文件。进度通知可取消。取消不保存规划，不改知识快照。默认排除常见凭据、Git/Agent/编辑器配置、工具环境与知识目录，不跟随符号链接。过滤不能保证其他文本没有敏感内容；后续生成还须另行检查并确认发送范围。

只读 JSON 预览包含入选相对路径、文件指纹、大小和行数，以及跳过项统计。`summary.limited=true` 表示触及限额或有未覆盖的读取，不能当作完整覆盖。二进制、范围排除和受限内容分开计数；没有入选文件也不会凭空生成内容。硬性目录遍历上限为 10,000 项、深度 32。这里的字节限额是静态读取上限，不是模型 token 或费用预算。

## 保存和重新检查

检查预览后运行 **Repo Knowledge: Save Generation Plan**。它会重新扫描，拒绝已变化的文件、范围或覆盖信息，然后保存到外部知识目录的 `plans/<UUID>.json`。文件只有路径、指纹、统计和语言/限额，不包含源码正文。保存不等于授权调用模型或发布。

若知识目录在源码仓库内，保存会拒绝；请按现有接入指南使用外部存储。规划预览仍可用。更改配置或工作区后请重新规划。保存过的规划不原地覆盖；如提示数量达到 200，请备份后明确归档旧规划。运行取消后可重新发起扫描，不会自动续扫或生成。

## 明确确认后生成候选

新仓库先运行 **Initialize External Store**；已有知识不会被覆盖。随后运行 **Plan Knowledge Generation**，检查只读规划。Save Generation Plan 可选，保存不授权生成；同一窗口会保留该次预览。窗口重新加载、配置或根目录变化后需要重新预览。

运行 **Generate Knowledge Candidate**，选择最多 2/4/8 张卡片。弹窗会列出本次文件、语言与上限，只有点击 **开始生成 / Generate** 后才预检并发送所选已保存源码。取消弹窗不调用后端；进度通知可取消。不要在生成期间改动源码或知识，变化会导致候选被拒绝。成功只保存到 **New Cards**，请按[工作台手册](workbench.zh-CN.md)检查正文与引用，再单独确认发布。生成不自动发布，也不修改或执行源码。

使用当前宿主配置的 Codex 模型/提供方；本插件不复制令牌、不改登录或模型选择。Windows 和 SSH 路径分开，自动发现失败时设置该宿主的 repoKnowledge.codexExecutable。此预览只验证 CLI 0.164.0-alpha.11.1 的 gpt-6.1-sol/gpt-6-astra/gpt-6-sol/gpt-6-luna，以及 CLI 0.162.0-alpha.17.2 的 gpt-6.1-sol。其他版本/模型会在传入源码前拒绝，不自动切换。受限兼容策略与本次验收范围详见 [ADR 0008](../architecture/adr/0008-explicit-codex-generation.md)。

当前上限：单次显式任务、总时限 60 秒、编码源码包 128 KiB、输出 64 KiB，以及观测到的用量/事件限制。这些不是精确费用或计费调用次数上限；统计可能延迟。没有自动重试。确认后保存元数据任务记录，成功后需重新规划才能发起另一任务；找回结果及同一任务的显式重试见下节。

若返回 TURN_FAILED，界面仅保留固定阶段、错误类别和可用时的 HTTP 状态，不显示原始提供方错误。network 只是分类，不证明特定网络根因或账号已退出；不必自动重登录。Windows 曾因独立后端网络路由失败；使用正确启动环境后已保存有效候选，Remote SSH 也已成功。Diagnose Generation Backend 的 configured 只说明账户/配置预检，不证明模型请求成功。

模型访问、生成成功、引用校验、候选保存与确认发布是不同门禁。T16 已实现元数据检查点、结果找回和显式重试，两端在本次自编演示中已通过结果找回、无结果重试与进度取消。M3 本次范围验收完成，仍是未发布开发功能；不保证其他代码库的生成质量。

## 找回结果或显式重试

新版本在确认生成后，把不含源码正文的任务记录保存到外部知识目录的 generation-jobs。窗口重载不自动启动任务。主动运行 **Repo Knowledge: Recover or Retry Generation Job**，选择该目录下的任务：

- 若候选已经完整保存，核对版本和引用后直接找回同一候选，不启动模型。请去 New Cards 审阅；该操作不发布。
- 若候选已进入发布历史，只报告已处理，不重新生成或发布，即使后来已删除该批卡片。
- 若没有候选，需要再次确认文件范围和发送源码。重试是新的有时限尝试，可能产生新用量，不是续接原模型对话。源码或正式知识变化时拒绝重试，请重新规划。
- 若已有候选但过期/损坏，拒绝采用，也不会悄悄替换它。保留文件检查，另行规划新任务。

旧版本生成的候选没有任务记录，继续从 New Cards 审阅，不会自动转换成可恢复任务。任务记录不保存源码包、模型提示词、部分输出或凭据；最多保留 100 个任务，归档前备份完整知识目录，包含候选和发布历史。格式及降级规则见 [ADR 0009](../architecture/adr/0009-generation-job-recovery.md)。

`JOB_BUSY` 表示该任务仍持有执行锁，也可能是进程崩溃遗留。插件不根据时间/PID 自动接管。完整候选仍可找回；没有结果时应停止重试，先确认原后端已停止并备份完整存储，再由维护人员处理对应锁。不要删除整个知识目录或发布历史，也不要用循环重试绕过锁。当前没有引导式异常锁恢复；取消通知也不是后端计费一定停止的保证。
