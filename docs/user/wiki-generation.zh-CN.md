# 生成 Wiki 文章与关联卡片（开发预览）

此功能尚未发布到 GitHub Release 或插件商店。旧 M1 安装包没有这些界面。
当前可以生成和阅读独立候选；正式文章发布及存储升级仍在 T27.4 开发范围。

1. 在所需 Windows 本机或 Remote SSH 工作区打开 Repo Knowledge 主页，进入生成面板。
2. “生成内容”选择 **Wiki 文章＋关联卡片（预览）**。填写包含/排除范围、语言、文件/读取上限，以及最多关联卡片数 2/4/8。
3. 点击“预览源码范围”，检查页内清单。覆盖不完整或空范围不能开始；修改任一表单字段必须重新预览。
4. 点击“确认并生成候选”。另一个确认框会列出即将发送给本宿主配置模型/提供方的已保存源码；取消不会开始模型请求。
5. 确认后运行一次受限模型任务，最多 60 秒，输出最多 64 KiB，最多 3 篇概述/架构/模块文章及所选数量的新卡片。可取消；失败不自动重试，也不改变登录、提供方或代理。
6. 保存成功后，面板显示文章和关联卡片数量。点击 **查看 Wiki 候选** 打开目录和 Markdown 阅读器。事实块引用同批未发布卡片；额外说明仅为模型推测，不能冒充人工设计理由。路径和证据行号目前显示为文字，暂不跳转。
7. 关闭后需要找回时，在面板点击 **找回已保存 Wiki（不重试）**，选择已有结果，再点击“查看 Wiki 候选”。它只读取已保存文件，不启动模型，不创建第二份结果。没有成功保存时，请重新预览后决定是否再次生成；这会是新的一次模型用量。

Wiki 候选与卡片 New Cards 队列不同：它们作为一整份文章＋卡片候选保存在外部存储 `wiki-candidates` 目录，不能通过 v1 卡片发布命令单独发布。当前不改正式知识、MCP、源码或历史，不自动迁移格式。正式 Agent 检索仍读取原来的已发布卡片。

阅读器会重新核对保存时的源码/基线；变化时显示过期或拒绝跨上下文读取。`current` 只表示本次引用/源码匹配，不证明推测、业务历史或模型正文正确。Markdown 不执行 HTML，不加载正文链接、图片或命令。请先人工核对事实；正式文章审阅、确认发布、历史及回退要等后续兼容门禁完成。

模型入口、取消和预览均已有自编夹具自动检查；这一切片尚未增加真实模型、视觉布局或真实 Remote SSH 的最终验收，不能据此宣称任意仓库生成质量。底层范围限制和配置要求见[生成指南](generation.zh-CN.md)；兼容与恢复规则见 [ADR 0016](../architecture/adr/0016-wiki-generation-staging.md)。
