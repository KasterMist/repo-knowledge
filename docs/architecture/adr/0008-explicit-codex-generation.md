# ADR 0008: Explicit constrained Codex generation into reviewed candidates

Status: accepted for M3 development; real generation acceptance remains open. Date: 2026-10-27.

## Decision

Expose Generate Knowledge Candidate only as an explicit command in a trusted workspace with a current, nonempty, fully covered T14 preview. Saving a plan retains that in-memory preview; configuration/workspace changes clear it. Generation asks for a page limit, displays selected paths/language/time/output limits and requests modal confirmation before any backend preflight or source transfer. Unsaved source/knowledge editors block it. Only one dialog/task may run per extension instance; disposal/cancellation propagates to the owned backend. Opening/saving source never starts generation.

The core adapter revalidates a selected-source packet and canonical base, checks the CLI's version, and starts restricted app-server processes in scratch storage outside the repository and knowledge store. The executable must also resolve outside the target repository. CLI overrides disable known shell/code-mode/apps/plugins/browser/computer/image/workspace/agent/hook/auxiliary execution surfaces, web search, notify commands and project-document loading. Model/provider/login settings are not rewritten. The first process reads configuration without starting a thread; the second explicitly disables each inherited MCP server and rechecks effective settings. An empty mcp_servers override alone is insufficient because inherited entries can remain.

This development preview admits only known version/model combinations: CLI 0.162.0-alpha.17.2 with gpt-6.1-sol, and CLI 0.164.0-alpha.11.1 with gpt-6.1-sol/gpt-6-astra/gpt-6-sol/gpt-6-luna. Custom model catalogs and unrecognized enabled feature flags are rejected; an explicit allowlist preserves passive auth/model-discovery/network-routing/speed options. Model/provider changes between preflight processes or at thread creation are rejected. Do not silently switch the configured model or admit future versions. Compatibility expansion needs current tool-surface evidence. These gates rely on a trusted selected Codex binary; this is not isolation from a malicious executable or a hostile local filesystem process.

The adapter preserves the configured model/provider, confirms account availability without requesting token refresh, creates a separate ephemeral readonly thread, overrides base/developer instructions and rejects unexpected instruction sources or a changed model/provider. It checks retained creation identities and refuses prepared history before generation; the prompt includes permanently reserved IDs so removal does not encourage identity reuse. It rechecks source/base before the thread and verifies thread settings before submitting source. It then collects one bounded turn, validates current selected-source references/canonical knowledge and saves only an ADR 0007 creation candidate. It never invokes the publisher. The target's source, tests, builds and benchmarks are not run. Source comments are untrusted model input and conclusions remain subject to human review.

## Cancellation and failure

The initial UI limit is one explicit task, a 60-second whole-job deadline and at most 2/4/8 pages; source packet/turn/output/event/observed-usage ceilings from the core boundaries remain in force. Byte/time/observed-usage limits are not a guaranteed money or billable-call cap. The client attempts interruption and owned process-tree cleanup. Saving a candidate accepts cancellation, removes its exclusively created candidate file when cancellation/failure interrupts that save, and never changes canonical knowledge. A failed generation is not silently retried and does not publish. Raw upstream errors are reduced to fixed error/phase/reason and an optional numeric HTTP status; no endpoint/token/raw response is logged in the UI report.

Generation-job checkpoints, result adoption after an interrupted UI and idempotent explicit retry are not implemented. The plan preview remains available after an unsuccessful attempt; another explicit command is a new job, not automatic continuation. Success consumes that preview and requires fresh planning for another job. Disk/OS failures retain the filesystem limitations documented in ADR 0005/0007; stop and preserve evidence on cleanup errors.

## Persistence and rollback

No new persisted schema or activation-time migration. T14 plan format 1, canonical knowledge format 1, creation candidate format 1 and history formats 1/2 remain unchanged. Scratch folders are external and removed only when empty; no recursive cleanup touches user files. Generated candidates follow the existing review/confirmation/publication/removal workflow. To disable generation, reinstall the prior extension; preserve the complete knowledge directory and respect ADR 0007's downgrade restrictions on newer creation history. Published release assets remain unchanged.

## Verification and remaining gates

Unit/peer tests cover restricted arguments, version/model/config/MCP rejection, no in-repository executable/cwd, cancelled candidate saves and sanitized upstream errors. Packaged-editor tests verify that Generate without a reviewed plan stops before any dialog/backend/model action. Offline no-auth mock-provider captures and actual-host preflight are separate from real inference. Two Windows self-authored demo attempts reached a real turn but failed upstream; the second retained a network category, neither saved a candidate or changed canonical bytes. A Linux Node 22.22.1 standalone probe passed the restricted configuration stages but account/read returned RPC_REJECTED/network before thread creation; canonical bytes were unchanged. Do not claim a successful generation, invalidate earlier actual-host diagnostic acceptance or infer a specific network root cause from these categories. Windows/Remote SSH real output, source citations, cancellation/recovery and new-batch confirmation acceptance still gate M3 completion.
