# Repo Knowledge：任务路线图与里程碑

更新：2026-10-23。所有者：KasterMist。许可证：Apache-2.0。仓库名 repo-knowledge。Windows 与 Linux 均为必需平台。

当前状态：M0 工程基础已公开，双平台 CI 已通过，治理仍有待办。M1 核心实现完成；Remote SSH 官方 Codex 的四工具、新对话复用及过期证据恢复已有人工验收和独立文件核对，原生平台、剩余编辑器/错误恢复及 alpha 发布仍未完成。任务状态与续接步骤统一见[项目任务与进度总表](../development/project-status.zh-CN.md)，详细证据见 [Issue #3](https://github.com/KasterMist/repo-knowledge/issues/3) 和 [验收记录](../development/m1-acceptance.md)。任务 ID 是规划编号，不能当作 GitHub Issue 编号。

生成边界：由用户决定是否生成 Wiki/卡片，并主动发起扫描、首次生成、重新生成和增量更新。代码变化不得静默触发模型调用或知识重写；生成候选经用户审阅确认后发布。

## 1. 里程碑与发布含义

| 里程碑              | 对应技术阶段 | 对外结果                       | 退出条件                                   |
| ------------------- | ------------ | ------------------------------ | ------------------------------------------ |
| M0 开源工程基础     | 新增准备阶段 | public 源码仓库，明确开发中    | 许可证、贡献规范、CI、Issue 体系具备       |
| M1 Codex 接入预览   | P0           | 第一份可安装 alpha VSIX        | 三卡片查询、证据读取、候选提交与新会话复用 |
| M2 知识工作台       | P1           | 用户可编辑的 Wiki 与卡片       | 同版本读取、修订保护、审阅与回退           |
| M3 用户发起首次生成 | P2           | 用户确认范围后为小仓库生成知识 | 可取消、引用可检查、失败可恢复             |
| M4 增量维护 beta    | P3           | 代码与知识共同演进             | 失效追踪、未提交变化、分支隔离、冲突保护   |

源码可以在 M0 公开，功能版本按后续里程碑发布。M0 不能描述成“已实现 Qoder Repo Wiki”；M1 不能描述成已支持全量或增量生成。

## 3. 首轮建议执行顺序

1. T01–T03：形成干净、可检查的独立仓库基础。
2. T04：发布开发中源码，建立 Issue 和里程碑，将本表任务映射到真实链接。
3. T05–T09：先证明官方 Codex 的知识闭环。
4. T10：发布带清晰限制的 alpha VSIX，收集实际使用反馈。
5. 每个里程碑结束更新风险和工作量，再决定下一轮范围。

P0 中原有的 2–4 个有效工作日不包含新增开源治理准备。M0 暂估增加 2–4 个有效工作日；没有在此时给出具体日历交付日期。

## 4. Issue 模板内容

```markdown
## 用户场景

谁在什么任务中遇到什么问题？

## 本次交付

用户可见行为、涉及模块和公开接口。

## 依赖

规划任务 ID；落地后替换/补充 GitHub Issue 链接。

## 验收

- [ ] 可观察的结果
- [ ] 错误和恢复路径
- [ ] 必要测试或真实 IDE 验收证据

## 范围外

明确不属于该工作包的能力。

## 文档与兼容影响

配置、知识格式、升级、隐私或版本变化。
```

## 5. PR 模板内容

```markdown
## 问题与结果

修改前的触发方式和修改后的行为。

## 关联任务

Closes #实际编号

## 验证

执行命令、结果；人工验证环境和证据；尚未覆盖的部分。

## 兼容与迁移

数据、配置、协议变化；回退方式。

## 文档

用户说明、架构决策及 changelog 的对应修改。
```

不能将占位 `Closes #实际编号` 原样提交到 GitHub。任务状态由验收证据驱动，不按投入时长或生成代码量判断。
