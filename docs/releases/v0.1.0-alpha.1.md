# Repo Knowledge v0.1.0-alpha.1

First GitHub-only alpha preview. VSIX/product version: **0.1.0**. Knowledge format: **schemaVersion 1**, unchanged. This is not a Marketplace publication or a full Repo Wiki generator.

## Included

- Three self-authored knowledge cards with source references and freshness reporting.
- Standalone MCP: get_knowledge_status, search_knowledge, read_knowledge and propose_knowledge_update.
- Revision/snapshot conflict checks and stale-evidence rejection. Proposals remain pending; tools never overwrite published knowledge or target source.
- Six VS Code commands for external storage, card search, snapshot browsing, MCP diagnostics, Codex setup preview and the demo.
- Windows-native and Windows Remote SSH to Linux workflows. Remote execution can use the existing VS Code Server Node without installing system Node/npm.

## Compatibility and evidence

Validated editor baseline: VS Code 1.117.0 x64. Native MCP development/runtime baseline: Node 24.19.0; Linux Remote SSH MCP additionally tested on Node 22.22.1. Maintainer-reported official Codex acceptance used extension 26.51007.21434: four tools, independent conversation, conflicts, stale evidence and restoration. See the repository's M1 acceptance record for evidence categories. The 0.1.0 release changes version/package/release handling; it introduces no new knowledge-tool semantics.

Real Windows/Linux editor-host CI is distinct from native Linux desktop Codex, which remains unverified and outside this alpha's claim. WSL, macOS and ARM64 are not claimed supported. Other MCP agents have no product-specific acceptance yet. The manifest's earlier minimum VS Code version is provisional; use the tested baseline.

## Install and configure

Download repo-knowledge-0.1.0.vsix and SHA256SUMS from this release. Verify the VSIX SHA-256 before installation. In VS Code, select Extensions → … → Install from VSIX. In a Remote SSH window, install the extension on the SSH host. Reload the window, run Repo Knowledge: Open Three-Card Demo, then Diagnose Standalone MCP and Search Cards.

Native Windows: configure an absolute Node 24.19.x path in repoKnowledge.nodeExecutable if Node is not on PATH. Remote SSH: leave its default to use the remote extension-host Node. Run Show Codex MCP Setup and explicitly merge the preview into the configuration used by the active Codex backend, then restart Codex. Preview paths are host-specific. The plugin does not edit Codex configuration or collect credentials; one server entry targets one repository.

release-info.json records the source commit and VSIX digest. SHA256SUMS and GitHub asset digests establish file integrity, not independent publisher signing or a security audit.

## Limits and rollback

No Wiki generation, complete Wiki tree, review/publication UI or automatic knowledge maintenance. Future scans/generation/regeneration/model updates are user-initiated and require candidate review and confirmed publication. Existing demo cards are fixtures, not generated knowledge about your repository.

Back up your external knowledge store before upgrades. Remove or update explicitly configured MCP entries before uninstalling/moving the extension; regenerate their paths after reinstalling. To roll back, install a previously retained VSIX and restore your own store backup if needed. This release does not migrate schemaVersion 1 or delete external stores. Never replace an already published tag or asset; fixes get a new product version and release.
