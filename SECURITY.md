# Security policy

The project is pre-release and has no supported production version yet.

Do not post credentials, private code, exploit details or sensitive logs in public Issues. GitHub private vulnerability reporting should be enabled before accepting security reports; when available, use the repository's Security → Report a vulnerability action. If that action is unavailable, do not publish details; use a non-sensitive Issue to request a private reporting channel from the maintainer.

There is currently no advertised private email address or guaranteed response SLA. This document does not claim the GitHub reporting setting is enabled until it has been verified.
